## The shared interface — exact call and data shape

One module, so there are not "four unrelated copies of configuration
logic": `ops/devlane/harness/graft.py`, stdlib only, wire-speaking. It is
the single reader of the `GRAFT_*` conf keys and the single builder of a
Graft invocation. The launcher consumes it over the already-declared
`dispatch → harness` edge (dispatch/CONTRACT.md §"Dispatch is a
composition app"); the conductor consumes it over a `ops/bin/graft.sh`
lever. Independent contract and test producers author against exactly the
signatures and shapes below.

Placement rationale: harness owns isolation, probes, and external
surfaces (`ops/README.md` Layout row for `ops/devlane/harness/`). Graft
is an external surface. `dispatch → harness` is an allowed edge; `task →
harness` is not, and this plan adds no such edge.

upstream reads). `@nanonets/graft@0.17.0` returned HTTP 404 on npm on
2026-09-10, so install is from the pinned **source revision and its
committed lockfile**, never `npm install @0.17.0`.

### Conf keys (declared in `lane.conf`, read only by `graft.py`)

- `GRAFT_ENABLE` — `'1'` on, `'0'` off. **The one-line disable.** When
  `'0'` or absent, the lane behaves exactly as it does at this ref:
  `prepare_worker` returns `None`, the launcher records nothing under
  `harness.graft`, no check depends on Graft. PR 1 sets it `'1'` in the
  same change that lands the reader (closure needs both together).
- `GRAFT_NODE` — absolute path to the pinned Node binary (the install
  target under lane state, never a `/tmp` path).
- `GRAFT_BIN` — absolute path to the installed Graft entry script.

`graft.py` reads all three via `laneconf` so `closure` stays green.
Environment > `lane.local.conf` > `lane.conf` precedence is inherited
from `laneconf`.

### Functions

```
config(env=None) -> dict
    {"enabled": bool, "node": str|None, "bin": str|None,
     "pin": <pin.json>, "sources": {...}}
    Refuses class `graft-config` only on a malformed conf value
    (e.g. a relative GRAFT_NODE). "disabled" is a returned state, never
    a refusal — absence is declared, not inferred.

available(env=None) -> (bool, str)
    Measured. (True, "") when node+bin exist, are executable, and the
    live `graft --version` / `node --version` match pin. Otherwise
    (False, reason) where reason distinguishes:
      "disabled"                — GRAFT_ENABLE off/absent
      "absent: <what>"          — looked, node/bin/pin not present
      "UNREACHABLE: <what>"     — could not look (spawn error, etc.)

cache_dir(root: Path, job_dir: Path|None) -> Path
    ALWAYS outside the source tree, per resolved worktree/snapshot,
    never one shared graph per git common dir:
      dispatch  -> job_dir / "graft-cache"
      worktree  -> ${XDG_STATE_HOME:-~/.local/state}/<LANE_NAME>/graft/<root-id>
    where <root-id> is a stable hash of the resolved root path.

invoke_argv(subcommand, root: Path, cache: Path) -> list[str]
    [GRAFT_NODE, GRAFT_BIN, subcommand,
     "--only-dir", "ops", "--dir", str(cache),
     "--no-gitignore", "--no-ignore", ...]
    No shell. subcommand is restricted to the read set
    {map, ask, skeleton, callers, grep, check-freshness}; a write verb
    (init and anything else) refuses class `graft-readonly`.

invoke_env(cache: Path, graft_home: Path) -> dict
    {"GRAFT_DIR": str(cache), "GRAFT_NO_REFRESH": "1",
     "GRAFT_NO_GITIGNORE": "1", "GRAFT_NO_IGNORE": "1",
     "DO_NOT_TRACK": "1", "CI": "true", "HOME": str(graft_home)}
    prepare also seeds a fresh <graft_home>/.graft/update-check.json so
    the CLI's always-run maybeRefreshInBackground makes no npm subprocess.

build_context(root: Path, cache: Path, env) -> dict
    Runs a read subcommand offline; returns
    {"schema": "agentscient.graft/v1", "root_scope": "ops",
     "authority": "navigation-only",
     "graft": {"version": ..., "source_rev": ...},
     "generated_offline": true, "map": {...},
     "unresolved": null|str}
    A successful CLI exit is NOT taken as fresh: if refresh fell back to
    stale, or exit is nonzero, `unresolved` carries the reason and `map`
    is whatever was safely read. Graph context is navigation evidence,
    never contract authority — hence the constant "authority" field.

prepare_worker(job_dir: Path, snapshot: Path, env) -> dict|None
    The launcher seam. If disabled -> None (no effect).
    If enabled but not available -> raise, launcher projects
      `graft-unavailable` BEFORE minting the child.
    Else: build cache OUTSIDE snapshot, write
      job_dir/context/graft/context.json (read-only view for the worker),
      seed the worker graft home + update-check.json, verify
      `git -C snapshot status --porcelain` is EMPTY (else refuse
      `graft-residual`), and return
      {"enabled": true, "available": true, "source_rev": ...,
       "graft_version": ..., "cache": str, "context": str,
       "unresolved": null|str}
    recorded verbatim under harness.graft in the dispatch record.
```

### CLI / lever (the conductor entrypoint "now")

`ops/bin/graft.sh` → `python3 ops/devlane/harness/graft.py <verb>`:

- `status` → exit 0, prints resolved availability (enabled/disabled/
  unavailable with the measured reason).
- `context [--root PATH]` → exit 0, prints the `agentscient.graft/v1`
  context JSON for `ops/` (what a conductor reads now, in a worktree).
- `map|ask|skeleton|callers|grep …` → pass-through with the safe flags
  and the outside-tree cache; a conductor navigating `ops/` by hand.
- Refusal wire (stderr, exit 2, empty stdout, one line
  `class: expected …; found …; needed …`): `graft-config`,
  `graft-unavailable`, `graft-disabled` (an action verb while disabled),
  `graft-readonly` (a write verb), `graft-residual`.

### The record field

`harness.graft` in the dispatch record is the declared, absence-explicit
byproduct: `{enabled, available, source_rev, graft_version, cache,
context, unresolved}`. Disabled runs omit it or set `enabled:false`; a
build that could not look sets `available:null` and a non-null
`unresolved`. Nothing here is a real spend claim.

## The edges, and their six obligations (docs/verified-couplings.md)

One new edge: **lane → Graft (external surface)**, consumed by the
launcher and the lever.

1. **Closure both ways.** The edge is declared in
   `ops/devlane/harness/CONTRACT-graft.md`; the live counterparty is
   re-checked by `graft_probe.py`. A launcher that shelled `graft`
   without the contract would be a dark coupling — forbidden.
2. **Shape.** argv/flags/env and the `agentscient.graft/v1` context JSON
   conform, checked mechanically in `test_graft_contract.py`.
3. **Behavior.** The probe fires on planted faults (missing bin →
   `UNREACHABLE`; stale fallback → `unresolved`) and stays quiet on a
   clean mock, per `probes.md`/`concerns.md` calibration.
4. **Freshness.** `pin.json` stamps node sha + graft source_rev + date;
   any binary move voids the probe verification and re-demands it. A
   `graft --version` that disagrees with pin refuses `graft-unavailable`.
5. **Permission.** `dispatch → harness` is the allowed edge; the read
   core (`lane_read`/`lane_mcp`) must NOT depend on Graft, and does not.
   `GRAFT_ENABLE='0'` is the removal-for-one-config-line the obligation
   prices.
6. **Blast radius.** A graft version bump or node move re-verifies this
   one edge (probe + the contract/mock tests), never re-integrates the
   lane.

## Walkthrough of the first run

A first dispatched read job (say `adversarial-review` on a `lane/…`
branch) with `GRAFT_ENABLE='1'`, traced against the real environment.

1. **Admission (`_launch`).** Worker resolved via `laneconf.worker`;
   ref/lineage/scope checks as today. New: nothing yet — Graft prep runs
   after the snapshot exists.
2. **Snapshot mint (`_snapshot`).** Fresh `git init` + fetch + `checkout
   --detach <ref_sha>`; no origin, no `logs/`. The tree is `ops/…` and
   nothing else.
3. **Graft prepare (`graft.prepare_worker`), on the host, before the
   child.**
   - Disabled? Return `None`. No `harness.graft`, run proceeds exactly as
     at this ref. *(No improvisation point: absence is declared.)*
   - Enabled but node/bin/pin missing — the state measured **right now**
     (`which node` → absent)? Refuse `graft-unavailable`: *expected the
     pinned Node+Graft at GRAFT_NODE/GRAFT_BIN matching pin.json; found
     <what is missing>; needed run `ops/devlane/harness/graft/install.sh`
     or set `GRAFT_ENABLE='0'`.* No child is minted. **This is the
     refusal that stands where a worker would otherwise try to `npm
     install` or stub a tool.**
   - Enabled and available: build the cache at `job_dir/graft-cache`
     (**outside** `snapshot/`), invoke `graft map --only-dir ops --dir
     <cache> --no-gitignore --no-ignore` with `GRAFT_NO_REFRESH=1`,
     `GRAFT_DIR=<cache>`, seeded `<graft_home>/.graft/update-check.json`,
     `DO_NOT_TRACK=1`, `CI=true`. The **no network** environment cannot
     provoke `maybeRefreshInBackground` because the seed + `NO_REFRESH`
     stop the npm subprocess. If the seed cannot be written, refuse
     `graft-unavailable` — never let the CLI reach the registry.
   - Write `job_dir/context/graft/context.json` (`authority:
     navigation-only`). If the CLI exited 0 but refresh fell back to
     stale, set `unresolved`; a successful exit is not fresh evidence.
   - **The read-only git directory guard:** run `git -C snapshot status
     --porcelain`. It must be empty (the cache is outside; `--no-gitignore
     --no-ignore` stop `.gitignore` edits — note `.graft` is **not** in
     `.gitignore`, so a stray `.graft/` in the tree would be a residual
     `??` and would invalidate the read job at `_settle`). If not empty,
     refuse `graft-residual` before the child. **This is the refusal that
     stands where Graft would otherwise write the tree.**
4. **Child launch (`_run_attempt`).** Claude runs under flags-isolation
   (operator uid, real HOME); codex/grok/agy under a relocated minimal
   HOME. The worker does **not** need node on PATH — the wrapper invokes
   the absolute `GRAFT_NODE`/`GRAFT_BIN`. `context/` is already an
   `--add-dir` for Claude read jobs (measured: `_argv` ll. 549–553 adds
   `out`, `in`, `context`); codex read jobs are `read-only` — so the
   worker **reads** `context/graft/context.json` as data. If the worker
   wants a live query, it calls the read-only wrapper, which carries the
   safe flags; a write verb or `init` refuses `graft-readonly`. **Refusal
   at the improvisation point: the worker cannot run `graft init` or any
   write verb; the wrapper exposes only the read set.**
5. **Each job prompt's demands.** The six input-less jobs (measured in
   `jobs.json`) mean the scope sentence must name
   `in/ag-graft-inventory-20260910.md` explicitly until PR #78. The
   worker is told inputs live under `in/`.
6. **Settlement (`_settle`).** Read role: `HEAD == ref_sha` (Graft never
   committed), residual empty (cache outside the tree) → envelope valid.
   `harness.graft` records what was built and any `unresolved`.
7. **The self-hosted runner / CI.** `ops/bin/suites.sh` runs nine suites
   + `ruff check .` + `laneconf closure`/`literals`. The runner has **no
   node** (same `which` result). So every Graft **unit** test runs
   against the fakes and is fully offline and green; the **native** tests
   (`graft_probe`, `test_graft_offline_worker`) detect an absent node and
   report **UNREACHABLE / skip with a declared reason**, never a pass and
   never a red — silence is not a declaration (`probes.md`). The native
   probes are run by hand on a warmed host before `graft-launch` lands.

## Decisive native probes (run on a warmed host before `graft-launch`)

- **P-GRAFT-INSTALL** — `install.sh` reproduces Node (sha match) and
  Graft (source rev); `node --version`/`graft --version` match pin;
  offline after one warm.
- **P-GRAFT-STRUCT** — `graft map --only-dir ops --dir <ext>
  --no-gitignore --no-ignore` offline exits 0, emits a map, leaves `git
  status --porcelain` empty, writes no `.graft` in the tree, and does not
  edit `.gitignore`.
- **P-GRAFT-NONET** — under a network-denied wrapper: with
  `GRAFT_NO_REFRESH=1` + seeded `update-check.json`, no registry
  subprocess; without the seed, the subprocess is observed (the guard is
  proven load-bearing).
- **P-GRAFT-SNAPSHOT** — the same, run inside a real dispatch snapshot
  (detached, no origin): cache in `job_dir`, read-role settlement valid.
- **P-GRAFT-WORKER** — a tiny dispatched read job with Graft enabled
  produces `context/graft/context.json` and leaves the snapshot
  unchanged; the envelope is not invalidated.
