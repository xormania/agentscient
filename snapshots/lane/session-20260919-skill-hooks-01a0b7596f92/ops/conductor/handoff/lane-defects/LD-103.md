| where | ops/bin/suites.sh, the `ops/conductor/tests` suite split into four concurrent shards (`test_[c]*.py`, `test_[l]*.py`, `test_[ow]*.py`, `test_[!clow]*.py`) |
| defect | `test_dispatch_wrapper.RowHermeticStore.test_jobs_root_under_world_state` (id `jobs-root-under-world-state`, origin issue 6) asserts the real checkout's own `HEAD` is unchanged across its run ("tests must not mutate worktree state"). Measured 2026-09-16 on `lane/session-20260916-launcher` at `a061609c`: it failed once under `ops/bin/suites.sh`'s default parallel mode, comparing two different HEAD shas read before and after; run alone (`python3 -m unittest discover -s ops/conductor/tests -p 'test_dispatch_wrapper.py' -k test_jobs_root_under_world_state`) it passed, and a single-process `python3 -m unittest discover -s ops/conductor/tests -p 'test_*.py'` ran all 1478 conductor tests clean, this one among them. The four shards share one real git checkout rather than a `testkit.World`, so any conductor test in one shard that touches the checkout's own `HEAD` (a commit, a checkout, a reset) can move it out from under a concurrently-running test in another shard that is trying to measure it. `suites.sh` split this directory for wall-clock parallelism with no declared read of which of its tests touch the real worktree's git state and which run inside isolation — the exact conflict this test's own assertion exists to catch is the one the sharding is exposed to, unmeasured. |
| repair | Measure which `ops/conductor/tests` modules touch the checkout's own git state (`HEAD`, the index, refs) versus operate entirely inside a hermetic `World`; then either shard the suite so no two HEAD-touching modules run concurrently, move the HEAD-sensitive assertions onto isolated worktree/testkit state, or serialize just that corpus. Accept the fix only once it holds green under `ops/bin/suites.sh`'s own parallel shape across a few repeated runs, not from one clean run — a race that fires 1-in-N is not falsified by N-1 passes. |
| tests | Planted fault: run this test concurrently, in the same process group, alongside another conductor test that changes `HEAD` (a git checkout/commit fixture), and assert it now fails — proving the repair actually serializes or isolates rather than merely not having collided this time. Clean neighbour: the existing single-process 1478/1478 conductor run, which must stay green. |
