# LD-41

| field | value |
|---|---|
| observed | 2026-09-15 |
| where | ops/devlane/harness/isolation.py build_home and ops/devlane/dispatch/launch.py _run_attempt; the grok credential path of every dispatch |
| defect | build_home plants the host credential as a symlink; the grok CLI renews the token by renaming a new file over that name, so the renewal (a new refresh_token and create_time) replaced the link with a regular file inside the job home and the host copy kept the login's token, which xAI rejects about 30 h after its create_time (LD-18). Measured 2026-09-15 on the host: 48 job homes held a renewed regular file, 222 still the link; the host copy carried the 2026-09-13 06:51 login; the CLI's own log shows every host-side silent refresh since 2026-09-11 answered RefreshTokenRejected and the owner asked to sign in again each time. The launcher's LD-18 age rule then refused the dispatch of 2026-09-15 at 39.1 h. Also: test_isolation_credential_age.py left one /tmp/cred-age-* directory per run (1220 counted). |
| repair | isolation.carry_back(harness, home, env): after every attempt the launcher copies a renewed regular file back over the host copy atomically (same mode), re-plants the link in the job home, and records the reading in the attempt (carried / linked / older / absent); an error is an unresolved reading, never a failed attempt. The fixture cleans its directory at cleanup. |
| tests | ops/devlane/harness/tests/test_isolation_credential_age.py ARenewedCredentialIsCarriedBackToTheHost (5 rows: newer file carried with mode and link restored, untouched link carries nothing, older file kept out, a carried credential passes the age rule again, a home-less harness carries nothing); ops/devlane/dispatch/tests/test_launch_credential_age.py test_a_renewal_by_the_worker_reaches_the_host_copy through the fake CLI's TASK_LAUNCH_RENEW_AUTH knob, which renames a file over the link as the real CLI does. |
