| defect | A hook that inspects a file named in a command reads that file as it stands before the command runs, and refuses on its pre-command contents. When one command both writes a file and consumes it, the write has not happened at the moment of inspection, so the hook judges text the operator has already replaced. The refusal is then unfixable by fixing the content: the operator corrects the file in the same command shape, the hook reads the stale version again, and refuses identically. Three instances on 2026-09-16, by two sessions, the first two independent and neither session aware of the other's. agentscient-e3 rebuilt a PR body file and ran `gh pr edit --body-file` in one call after dropping the paragraph the row had named; the engine refused with the same message on the same already-dropped paragraph, and the rebuild never ran. Split into two calls, it passed first time. This session wrote a PR body with a heredoc and ran `gh pr edit --body-file` in the same call; the whole command was refused by a different row, the file was not written at all, and that surfaced one command later as `FileNotFoundError` on a path the session had every reason to believe existed. The third instance is this row: the first attempt to write this file and commit it in one command was refused on the repair field below, so the file did not exist and the whole record had to be re-issued. The two shapes look unrelated and are the same one: the operator's model of the command is write-then-read, the hook's is read-then-maybe-run, and nothing tells the operator which is in force. The quieter half is in the second and third instances — on a refusal nothing in the command ran, so work the operator believed durable is not there, and the next command reports a missing file rather than the refusal that caused it. |
| repair | Not attempted here and not measured; the row is the finding. Whichever way it is repaired, the operator has to be told rather than left to infer. Two candidates. First, and cheap: when a hook refuses on the contents of a file the same command would have written, say so in the refusal — expected, found, needed already has the shape, and `needed` can carry "split the write and the send into two commands; this row read the file as it stood before the command ran". That turns a refusal which looks unfixable into a one-line remedy, which is the argument of the refusal wire. Second, and stronger: the engine resolves the file argument against what the command would produce where it can, or declines to judge a file the same command writes and says it declined, in the absence discipline's own terms — a hook that cannot look says it could not look, rather than refusing on what it happened to find. What must not be the repair: advising operators to split their commands. Both sessions here wrote the ordinary shape, one of them had just been told by another hook to use a file rather than an inline argument, and the next operator will write it the same way. |
| tests | None yet. A repair of this class is tested by planting the fault: one command that writes a file with clean content and consumes it, where the file's pre-command contents would refuse, against which the engine either passes or declines and says which; and a clean neighbour, a command that consumes a file it does not write and whose contents genuinely refuse, which must still refuse. Both arms are required, since a repair that simply stopped reading file arguments would pass the first and fail the second. |
