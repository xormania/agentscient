# LD-87 — an order that closes a lock row the next order needs

- **class**: order shape
- **opened**: 2026-09-16 by the XO (PT-7), against the XO's own order
- **status**: open; the remedy is a mechanism or a record, not a message
- **found by**: agentscient-db, by walking into it
- **against**: dev d919c982

## What happened

The XO gave one session two orders in sequence:

1. Re-point `lane/session-20260916-launcher`'s `until` to the literal
   `dispatched=1 bound_by-null=0`, then `deliverable.py done`, then `remove`.
2. Then wire `coordination_mcp.py` into the codex launch on that same branch
   and open one draft PR.

Order 1 removes the lock row for the branch. Order 2 opens a PR for it. The
`matrix:deliverable` row refuses a `gh pr create` for a branch the lock does
not name, so the second order could not be carried out after the first.

The hook was correct. The order shape created the gap.

## The remedy the session used

db re-added the row pointed at the **new** deliverable (`codex-mcp=on-dev`,
reading `short`), and said so in the `why` so the settled row is not read as
reopened. That is the right repair and it is not the fix: it depends on the
session noticing.

## Why this is a row and not a note to the next session

D-PATTERN-1 (owner, 2026-09-16): a failure pattern with a fix does not recur,
and the fix is a mechanism, a refusal, a test with a planted fault, or a
record the next session reads — never a rule relayed by message. Telling the
next coordinator "close the lock after the work, or re-lock before the PR"
is exactly the relayed rule that ruling forbids.

## The shapes a fix could take, none of them built

- `deliverable.py remove` refuses, on the wire, while the branch has an open
  PR or unmerged commits at origin — the lock knowing that a removal is
  premature rather than the operator knowing.
- `remove` warns when the caller is the session still holding the branch.
- The close skill, not an ad-hoc order pair, owns the sequence: work, PR,
  merge, then the lock row goes.

The first is the cheapest and refuses at the moment of the mistake. None is
implemented and this row does not claim one is.

## Rule stated for the interim, knowing a rule is not a fix

Close the lock row **after** the work, or re-lock before the PR. Written here
so it is a record and not a message; it stops being needed when one of the
shapes above exists.
