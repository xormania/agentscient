| repair | A branch's route to the trunk is a thing that can be absent, so it is declared rather than assumed. The shape is already in the lane: `handoff.py held --branch B` exits 1 while a branch still holds open threads. The same question for commits — a branch with commits not on the trunk and no open pull request — wants the same answer, on the same wire, and wants to be asked where a session already looks: the onboard reading, the board, or the lock. The stronger form refuses at the point of the merge: merging a pull request whose branch head has moved past the merged head says so. Note that instance (1) had no pull request at all, so a check keyed on "merged" misses it; the question is "commits not on the trunk with no open pull request", not "commits after a merge". |
