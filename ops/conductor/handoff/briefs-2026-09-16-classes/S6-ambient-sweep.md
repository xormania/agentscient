# S6 — ambient-sweep: the strict kit's driver, and the families

Adjacent to class 5 and the owner's word "strict". The wall session agentscient-e0 makes `ops/testkit` strict (no host PATH in a world; `ambient` names tools, resolved per tool; `World.git()` carries its own git). Measured by that session at 46639344: the strict kit fails 1,587 rows across the ten suites for one cause, a fixture running bare `git` or `python3` with nothing on the PATH; 38 modules spell `git` and 7 spell `python3` in their own argv; 157 modules construct a `World`. The declarations must land family by family in PRs before the kit's, and they must be harmless under today's kit (an `ambient` name that is not an environment variable is ignored by `hermetic_env` at 46639344, so `ambient=("git", "python3")` is a no-op today and a tool grant under the strict kit). T-48 names the driver idea from the 2026-09-15 kit migration (mig.py, a scratch script; four defects met, in that AAR).

## The mechanism, two slices

S6a, the driver, a lever `ops/conductor/tools/ambient_sweep.py` (placement `none`; it writes tree files and a record, never state):
- `ambient_sweep.py module PATH --strict REF`: builds or reuses a scratch worktree at the merge of HEAD with REF (the strict kit's pushed head; `stale-base` shape: refuse on conflict), runs `python3 -m unittest discover -s <dir> -p <module>` there through `instrument.run` with a timeout, reads the refused tool names from the strict kit's wire (the exact line is agentscient-e0's; the driver takes the pattern from one place, `AMBIENT_REFUSAL`, and refuses class `wire` when no line matches a failing run), edits every `World(` construction in the module in the working tree to carry `ambient=(<names>,)` (anchor-counted: a construction the driver cannot parse refuses class `anchor` naming the line; an existing `ambient=` tuple is extended, never replaced), syncs the module into the scratch, re-runs, and prints one line: `module <path>: refused <names>; declared; rows before <n> after <m>` with exit 0 on green, 1 on a red that remains, 2 on a refusal.
- `ambient_sweep.py family DIR --strict REF [--modules FILE]`: every module in the family (or the listed ones), in file order; one JSON line per module appended to `ops/conductor/handoff/census/ambient-sweep-<date>-<family>.jsonl` (module, names, before, after, sha of the edit); exit 1 if any module stayed red.
- Never a commit: the builder commits the family with trailers and the driver's lines in the body.
Planted faults (`ambient_sweep_faults.py` on a copy of the driver): M-blind-wire (the wire pattern ignored; `reads-refused-names` goes red), M-replace-ambient (an existing ambient tuple replaced; `extends-existing-ambient` goes red), M-unanchored (an unparsed construction edited anyway; `refuses-unknown-shape` goes red). Rows (`test_ambient_sweep.py`, each executes the driver on a planted module and a planted strict-kit stub in a World and asserts what it did): reads-refused-names, declares-once, extends-existing-ambient, refuses-unknown-shape, rerun-green-exit-0, record-line-per-module, no-commit. Builder: an Opus session, after the kit's refusal line is pushed by agentscient-e0.

S6b, the families, ten suites (ops/devlane/{dispatch,harness,task,telemetry,hooks,fixtures,workflow}/tests, ops/testkit/tests, ops/conductor/tests, .claude/skills/pr-overview/tests), each a PR from a session branch; the failing-module list from agentscient-e0 sizes them. Sessions: agentscient-c8 runs the small families (task, telemetry, fixtures, workflow, pr-overview, harness) in one branch each; an Opus session runs conductor (the largest) and dispatch; hooks and testkit are wall paths and belong to the wall session. Each family PR: the driver's record file, the module edits, `ops/bin/suites.sh` green on today's kit at the head, the family's discover green on the merge with the strict ref, both pasted.

## The rules every build follows

- No producer owns two consecutive artifacts: the tests come from a dispatched Grok `author-tests` job, Codex `check-tests` reads them, the builder codes against the sealed tests, Grok `adversarial-review` and Codex `security-audit` read the pushed head. The builder never edits a test to reach green; a test that must change is a new tests commit by the test author, reviewed again.
- Every test case executes the subject and asserts what it did (the rule the wall session adds to docs/tests.md on 2026-09-16); a row that pins a count the contract does not own is a finding.
- Reviews and audits are dispatched against the pushed head, never an unpushed worktree commit.
- Every subprocess in a test goes through `ops.testkit.run` with a timeout; the world is hermetic and ambient is named; a fake is planted through the registry.
- The red is pasted, never inferred: `FAIL:` with an `AssertionError` at the base sha, `Ran N tests ... OK` at the head, the same discover command, both in the code commit's body with the base sha (the tdd skill).
- Every commit carries `Source:` and `Co-Authored-By:`; every paragraph that claims carries its reading (the claim skill); the second producer's absence is said where the owner's hand grant stands in.
- Draft PR into dev, body per CONTRIB.md, `## Proof` naming corpus rows under `ops/conductor/handoff/probes/`; the ready flip waits for a closed `security-audit` record on codex `gpt-daybreak-blue-latest` at the head sha with every finding disposed (CONTRIB.md ready table, owner's rule of 2026-09-16); a push after the audit voids it.
- A CHANGES verdict is a stop, ruled on by agentscient-0d (the planner), never by the builder; report each PR to agentscient-11 by message with its number, head, readings and what was not measured.
